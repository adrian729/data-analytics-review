Understanding a problem is always the first step. From there, it helps to recognize which of six [problem types](/glossary#problem-types) you're actually facing — it shapes what data you need and how you'll use it.

| Problem type | What it means | Example |
|---|---|---|
| **Making predictions** | Using data to make informed decisions about how things may be in the future. | A company with data on location, media type, and new customers acquired can't guarantee future results, but can predict the best ad placement to reach a target audience. |
| **Categorizing things** | Grouping data based on common features. | Classifying customer service calls by keywords or scores to identify top-performing reps or correlate actions with satisfaction scores. |
| **Spotting something unusual** | Identifying data that differs from the norm. | A smart-watch company sets algorithms on aggregated health data to alarm when a reading doesn't trend normally. |
| **Identifying themes** | Grouping categories into broader concepts. | UX researchers group categorized interaction data into themes — user beliefs, practices, needs — to prioritize which features to improve. |
| **Discovering connections** | Finding similar challenges across different entities and using data to find common solutions. | A logistics company analyzes wait times at shipping hubs with a partner to determine schedule changes that increase on-time deliveries. |
| **Finding patterns** | Using historical data to understand how likely something is to happen again. | Analyzing maintenance data reveals that most machine failures happen when regular maintenance is delayed more than 15 days. |

**Categorizing vs. identifying themes** is the pair worth keeping straight: categorizing things assigns items to categories; identifying themes takes those categories a step further, grouping them into broader themes.
